# Сценарий демонстрации ECA на защите диплома

## Перед началом (5 мин до защиты)

1. Запустить систему: `docker-compose up --build`
2. Открыть http://localhost:5173 в браузере
3. Войти: **admin / admin**
4. Убедиться что Dashboard показывает данные (все 4 счётчика > 0)
5. Удалить тестовую запись "123" (ID=6) через /sequences если не удалена

---

## 1. Dashboard — обзор системы (1 мин)

- Показать 4 счётчика с **анимацией чисел** при загрузке
- Показать блок "Последние выполнения" — кликабельные строки
- Показать "Статус системы" — все 4 пункта зелёные
- Переключить тему кнопкой луны/солнца (верхний правый угол)

**Акцент:** _"Дашборд показывает текущее состояние системы в реальном времени"_

---

## 2. Последовательности — структура (1 мин)

- Перейти в `/sequences`
- Показать список: фильтр по статусу, поиск по названию
- Открыть **"Запрос позиционного отчёта после взлёта"**
- Показать 5 шагов: WAIT → EVALUATE → ACTION → WAIT → ACTION
- Нажать **"Изменить"** у шага 1 — показать модалку с конфигом
- Объяснить ветвление: SUCCESS → CONTINUE, FAILURE → следующий шаг

**Акцент:** _"Каждый шаг — декларативная конфигурация. Никакого кода для сценариев"_

---

## 3. Демонстрация — живое выполнение (2 мин)

- Перейти в `/demo`
- Выбрать сценарий **"Запрос позиционного отчёта"** (✈ RA-89050)
- Показать шаги в карточке слева **ДО** запуска
- Нажать **"Запустить"**
- **Наблюдать:** граф оживает — ноды меняют цвет, рёбра подсвечиваются
- Журнал справа показывает шаги в реальном времени
- Дождаться завершения — зелёный END или красный ABORT

**Акцент:** _"Система выполнила 5 шагов автоматически, без участия оператора. Граф — это визуальное доказательство исполнения"_

---

## 4. Хронология — временное измерение (1.5 мин)

- Перейти в `/timeline`
- Выбрать борт **RA-89050**
- Нажать **"Воспроизвести"** на скорости 1×
- Смотреть как события появляются последовательно: сообщения → запуски → шаги
- Переключить на **4×** — быстрый обзор всей истории
- Указать на статистику справа: обновляется в реальном времени

**Акцент:** _"Это и есть временная последовательность из темы диплома. Система фиксирует КОГДА каждое действие произошло"_

---

## 5. Журнал аудита (30 сек)

- Перейти в `/audit-log`
- Показать записи: кто, что, когда
- Указать на типы: LOGIN, SEQUENCE_ACTIVATED, USER_TOGGLED
- Нажать **"Экспорт CSV"** — скачается файл

**Акцент:** _"Полная прослеживаемость всех действий в системе"_

## Вопросы от комиссии

**Q: Почему Easy Rules, а не собственный движок?**
> Easy Rules — зрелая библиотека с тест-покрытием. Собственный движок
> потребовал бы тех же усилий, но без поддержки сообщества и с риском
> ошибок в edge-кейсах.

**Q: Как обеспечивается надёжность доставки событий?**
> Transactional Outbox: событие записывается в таблицу `event_publication`
> в той же транзакции что и доменное изменение. Spring Modulith гарантирует
> доставку при перезапуске без потери событий.

**Q: Что такое переход GOTO N?**
> Переход не к следующему шагу, а к шагу с конкретным индексом — для
> реализации циклов. Например: шаг 4 при FAILURE → GOTO 2 для повторной
> проверки условия.

**Q: Почему модульный монолит, а не микросервисы?**
> Для масштаба этой системы микросервисы избыточны. Spring Modulith даёт
> границы модулей как у микросервисов, но без сетевого оверхеда и
> распределённых транзакций.

**Q: Чем ECA отличается от существующих ACARS-систем?**
> Существующие системы — пассивный мониторинг (только отображение).
> ECA — активное реагирование: получил событие → выполнил цепочку
> действий по правилам. Это automation layer, а не monitoring layer.
