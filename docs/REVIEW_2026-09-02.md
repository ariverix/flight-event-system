## MEDIUM (сводно, детали — в исходных отчётах агентов, см. транскрипт сессии от 2026-09-02)

- БД: нет CHECK-констрейнтов на enum-подобные VARCHAR/JSONB поля (корень уже найденного бага V39); `execution_instances.sequence_id`/`refresh_tokens.user_id` FK без явных ON DELETE; нет индекса на `messages.message_type` отдельно; нет мастер-таблицы aircraft/flight.
- Архитектура: дублирование Audit-логики в 3 местах; `cluster` — единственный модуль без `package-info.java`; `execution` использует `sequence.port.out` (driven-порт) напрямую.
- Java: `JwtService` не follows constructor-injection паттерн соседей; `UserService.findByUsername/findById` возвращают `null` вместо `Optional`.
- TypeScript/React: WS-пейлоады кастуются без рантайм-валидации; `useTimeline` без race-guard (в отличие от `AircraftPicker`); два параллельных StepForm разошлись по полям; несмемоизированные `columns` в таблицах на WS-тике; `instancesStore` — subscription без reference counting; два независимых поллинга executions (список + колокольчик).
- Интеграция: Type B сообщения никогда не дедуплицируются (`externalMessageId` всегда null); ARINC 618 без MSGREF — та же дыра; нет джиттера в outbound backoff.
- Тесты: `frontend/components/demo/DemoPage.tsx` (~695 строк, нетривиальный async state machine с поллингом) — без единого теста.

## Позитивные наблюдения (агенты подтвердили как сделано правильно)

- RBAC path-level + method-level `@PreAuthorize` — консистентно везде, ни одного пропущенного эндпоинта.
- Refresh-token дизайн (SHA-256 opaque, ротация с reuse-detection) — качественный.
- Идемпотентность входящих ACARS-сообщений, circuit breaker, callsign matching — корректны.
- `CriterionEvaluatorTest` — образцовое покрытие граничных случаев (Off-timestamp clamping).
- `P1_9_ConcurrentStartDedupScenarioIntTest` — настоящая многопоточность, не мок.
- V38 unique-dedup index и SQL-инъекция в `RetentionService` (partition DDL) — обе защиты сделаны правильно.
- Оптимистичные блокировки + durable WAIT-claim в движке — солидный, задокументированный дизайн.
